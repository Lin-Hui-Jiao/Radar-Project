# vehicle_field512：车载雷达 512³ 功率密度场

为第二工作点（PSHC，工程 `/home/rootjiao/pshc`）生成输入场。本目录是新增的，独立构建，不修改本仓库已有文件。

- **场的计算：** 调用 `../field_export`（同为新增目录）。
  - 可见性：本仓库的 `RTree3d::Intersect3d` + `IntersectCallback`（`src/occlusion_utils.cpp`）。
  - 功率密度：`field_export/radar_kernels.hpp` 中的 `CleanKernel`，即 `Radar::CalculateSinglePointPowerDensity` 公式的双精度实现（V-double）。
- **本目录新增：** 站址检查和对齐检查工具 `site_check`、站址表 `sites.tsv`、驱动脚本 `run.sh`。

## 1. 场的定义

| 项目 | 取值 |
| --- | --- |
| 几何 | `test_area.3idx`（500 m 区域，瓦片 23_26、23_27、24_26、24_27） |
| 网格 | EPSG:2326 米制，1 m 间距，512 × 512 × 512 |
| 水平范围 | 东 834995–835506，北 815495–816006。即 500 m 区域（东 835000–835500、北 815500–816000）四边各外扩 6 m |
| 竖直范围 | 海拔 0–511 m（第 k 层海拔 = k m） |
| 节点 (i, j, k) | 东 834995 + i，北 815495 + j，海拔 k |
| 雷达 | 车载：安装高度 = 雷达处 `Getheight3d`（最高表面）+ `sites.tsv` 中的安装高度（V1 为 3 m；V1h 为 11 m，作者 2026-10-19 要求在 V1 基础上升高约 8 m）。站址必须通过第 3 节的检查，不能是屋顶或高架 |
| 扫描范围 | 方位 −180°～180°，俯仰 0°～90°（只照射水平面以上） |
| 数据版本 | V-double；交接格式见 `field_export/README.md` |

## 2. 坐标对齐

**R 树局部坐标 = EPSG:2326 −（836974.635391304153, 815456.572217391338）。** 依据：

1. **瓦片元数据。** `/home/rootjiao/build_index/build3dindex/test_dataset*/` 下全部 20 个瓦片的 `config.json`，`model_transform` 平移量都是这两个数。R 树中存的就是 OBJ 的模型坐标。
2. **瓦片边界。** 用这个偏移时，瓦片边界恰好落在 250 m 整倍数的 EPSG:2326 坐标上（东 835000、835250、835500，北 815500、815750、816000）。
   - `site_check cover` 实测：有三角面的整数节点为东 835001–835499、北 815501–816000。
   - 恰好落在边界线上的东 835000、835500 两列没有命中三角面。
3. **两份索引共用同一局部坐标系。** 500 m 与 1 km 索引用同一偏移时，重叠区 124,246 个节点的顶面高度完全相同（`site_check align`，实测）。

**与旧常量的差别：** master `Radar::Move` 写死的 (836975, 815457) 与上面相差 0.365 m、0.428 m。旧的 500 m 定高实验和 CSV 都用的是那组常量。

**经纬度：** 只用于幅值计算。节点和雷达都由 EPSG:2326 经 PROJ 反算（`field_export` 中的 `Proj`，按权威轴序处理）。
- 用 pyproj 独立复核：雷达经纬度相差 < 4×10⁻¹⁰ 度。
- 随机 2 万个非零节点用 pyproj + Python 重算幅值，最大相对差 5.9×10⁻⁸，即 float32 舍入量级（实测）。

## 3. 车载站址规则（`site_check site`）

| 规则 | 判据 |
| --- | --- |
| 地面 | `Getheight3d` 在站址处有三角面 |
| 街面，不是屋顶或高架 | 站址高度 ≤ 15 m 范围内顶面最低值 + 1.0 m |
| 平整，可停车 | 2 m 半径内顶面高差 ≤ 0.3 m |
| 车体到天线之间无遮挡 | 地面 + 0.05 m 到天线的竖直线段不与任何三角面相交 |
| 头顶开阔 | 天线到其上方 1000 m 的竖直线段不与任何三角面相交（不在桥下、树下） |

带搜索半径运行时，会列出附近通过检查的节点，按距离排序。

## 4. 用法

```sh
cmake -S vehicle_field512 -B vehicle_field512/build -DCMAKE_BUILD_TYPE=Release && cmake --build vehicle_field512/build -j
vehicle_field512/run.sh            # 生成 sites.tsv 中的全部站址
vehicle_field512/run.sh V1         # 只生成 V1
vehicle_field512/build/site_check site test_area.3idx -836974.635391304153 -815456.572217391338 835211 815751 3 8   # 查一个点并搜索附近 8 m
vehicle_field512/build/site_check section test_area.3idx -836974.635391304153 -815456.572217391338 ew 815754 834995 835506 -1 512 out.txt   # 真实网格截面（N = 815754 的竖直面）
python3 vehicle_field512/plot_slices.py V1h   # 切面图，见第 6 节
```

`run.sh` 对每个站址依次执行：
1. 站址检查（不通过则停止）；
2. 窗口覆盖统计；
3. `field_export`；
4. `field_check stats` 和 `field_check random`（随机 1 万个节点独立重算，要求逐位一致）；
5. `check_handoff.py`：检查文件是否为合格的 PSHC 输入，不合格则停止；
6. 在 PSHC 工程的 `data/` 目录下建软链接 `v512_<id>_vd.{f32,json}`。目录由环境变量 `PSHC_DATA` 指定，默认 `/home/rootjiao/pshc/data`；设为空（`PSHC_DATA=`）则不建。

增加站址：在 `sites.tsv` 加一行（东、北、安装高度、说明）。

## 5. 输出（即 PSHC 的输入）

`data/v512_<id>_vd.f32`（小端 float32，[z][y][x]，W/m²，被遮挡为 0，512 MiB）、`.json`（grid、value、sha256、provenance），以及 `.log`（全部检查的输出）。

- **格式：** 与 pshc `CLAUDE.md` 的"交接格式"一致。pshc 只读 `grid` 和 `sha256`，`provenance` 只作记录。
- **检查：** `python3 vehicle_field512/check_handoff.py data/v512_<id>_vd` 检查以下各项：
  - grid 各字段齐全；
  - `.f32` 字节数等于 nx·ny·nz·4；
  - SHA-256 与 `.json` 一致；
  - 全部值有限且非负（pshc_encode 的入口要求）；
  - value 的单位、类型、字节序、排列顺序；
  - provenance 的关键字段。
- **在 PSHC 中使用：** `cd /home/rootjiao/pshc && ./build/pshc_encode data/v512_V1h_vd out.pshc --eps 0.001`。
- **2026-10-19 实测：** V1、V1h 经 `run.sh` 重新生成，SHA-256 与此前逐位相同；在 PSHC 中按 `data/v512_<id>_vd` 读入，编码、解码后违反数 0（0.1% 时为 35,326 / 139,497 B）。

## 7. 已知情况

- **外扩带没有几何。** 12,644 列（4.82%，即 6 m 外扩带和恰好落在边界线 E 835000、E 835500、N 815500 上的列）没有三角面，另有 5 个单点空洞：(91, 87)、(125, 213)、(133, 237)、(44, 505)、(163, 505)。这些列没有地面和建筑，视线只会被区域内的几何遮挡。实测这些列在海拔 0–2 m 都没有非零值，即地下没有"漏光"。
- **接缝处高度探测失效（只影响 `Getheight3d`）。** 竖直探测线恰好落在 125 m 子瓦片接缝面上（i 或 j = 130、255、380）时，会与接缝处的三角形边共面而漏判。
  - `site_check cover` 因此把 738 个接缝列计成了"没有三角面"，实际上那里有几何。
  - 可见性射线不是竖直的，不受影响：实测接缝列在海拔 0–2 m 没有非零值。
  - 选站址时避开这几条线，否则站址的地面高度会算错。
- **PROJ 版本。** 场由系统 PROJ 8.2.1 生成。pyproj 自带的 PROJ 9.5.1 换算结果相差约 4×10⁻¹⁰ 度（0.04 mm），主瓣区可忽略，但旁瓣区对角度极其敏感，零点附近可放大到约 100%。逐位复现必须用系统 PROJ。
- **旁瓣区。** 俯仰 0°～90° 时，雷达水平面以下可见节点的值按方向图旁瓣计算，随角度振荡。
  - V1（海拔 < 8.68 m）：3,595 个非零节点，数值 1.9×10⁻⁶～5.7×10⁻² W/m²。
  - V1h（海拔 < 16.68 m）：152,576 个，数值 3.9×10⁻¹⁰～5.7×10⁻² W/m²。
- **雷达正下方的节点为 0。** 雷达正下方地面以上的节点可见，但俯仰为 −90°，偏离扫描范围 90°，核函数返回 0（与原程序 `PointPowerDensity` 的规则相同）。
  - V1 为 (211, 259, 6..8) 共 3 个，V1h 为 (211, 259, 6..16) 共 11 个。
  - 这些点不是被遮挡（`field_export` 统计为"visible but zero amplitude"），所以"0 = 被遮挡"在这一列上不成立。
- **近场。** 雷达正上方 0.32 m 的节点 (211, 259, 9) 为 246.8 W/m²（1/R² 公式在 R < 1 m 时已不代表实际物理量）。

## 8. 物理正确性评估（2026-10-19，实测）

运行方式：`vehicle_field512/build/vis_check test_area.3idx vehicle_field512/data/v512_<ID>_vd [随机数] [边界数] [种子]`；`python3 vehicle_field512/phys_check.py <ID>`。

**可见性：正确。**
- `vis_check` 不用生成器的 `Intersect3d` 遍历和带 EPSILON 的 Moller-Trumbore，改用 `RTree::Search`（按 1 m 分段取候选三角面）+ long double 符号体积的水密线段—三角形测试。
- V1、V1h 各取随机 2 万个、阴影边界 2 万个节点：全部一致，不一致 0。
- 反向对照：把 V1 的场配上 V1h 的雷达高度，检查器报出 1 万多个不一致，说明检查器本身有效。
- **与原程序的遮挡方法一致。** `field_export` 调用 `RTree3d::Intersect3d(雷达, 目标, IntersectCallback)`，与正式程序 `Radar::isOccluded`（`src/radar.cpp:996`）相同。
  - 被注释的 `FixedHeightComparator` 网格分支（`src/fixed_height_comparator.cpp:305–315`，提交 e416278 中曾启用）也是同一个调用。那里的 `Rect3d` 只是两点容器（min = 目标，max = 雷达），所以线段方向是目标 → 雷达。
  - 全场实测：把线段反向后，V1、V1h 的 1.34 亿个节点变化均为 0。
  - 唯一有实质影响的差别是 R 树坐标偏移。原程序用旧常量 (−836975, −815457)，本目录用瓦片 `model_transform` 给出的 (−836974.6354, −815456.5722)，见第 2 节。
  - 若改用旧常量，可见性变化的节点：V1 为 1,556,612 个（1.16%），V1h 为 1,090,136 个（0.81%）；雷达处地面高度也从 5.681 m 变为 5.608 m（全场实测）。
  - 需要与旧数据逐位一致时，可给 `field_export` 加参数 `--rtree-offset -836975 -815457`。

**主瓣幅值：忠实于生成公式，但公式里的 R 不是真实距离。**
- 原程序 `caltools::lon2xyz` 把地球当作半径 6371.193 km 的球来换算距离（源码注释："假设在赤道附近，纬度差转距离误差忽略"），`CleanKernel` 照搬了这一做法。遮挡几何则在 EPSG:2326 米制坐标中计算，两者度量不一致。
- 按真实距离（EPSG:2326 欧氏距离，或 WGS84 测地线，两者相差 < 3×10⁻⁶）计算的 S R² / K − 1：

  | 场 | 生成器自己的 R | 真实 R：最小 / 最大 | 平均 \|·\| |
  | --- | --- | --- | --- |
  | V1 | ±3×10⁻⁶ | −0.80% / +0.21% | 0.13% |
  | V1h | ±4×10⁻⁶ | −0.83% / +0.30% | 0.16% |

- 偏差随方位变化，竖直方向为 0。V1h 正北、正南 −0.82%，东北、西南 −0.28%。
- 成因（推导）：纬度 22.28° 处 WGS84 子午圈曲率半径为 6,344,595 m，卯酉圈为 6,381,208 m。用 6,371,193 m 的球计算，南北距离多算 0.42%，东西距离少算 0.16%，所以 S 在南北向偏小 0.833%、东西向偏大 0.315%，与实测一致。
- PSHC 拟合出的各向异性系数 1/a、1/b、1/c = 25.2437 / 24.9550 / 25.1646，与按曲率半径预测的 25.2438 / 24.9549 / 25.1646 一致，各向异性就来自这一误差。
- 影响：对压缩无害（7 系数模型能吸收），但最大 0.83% 的系统偏差大于 ε = 0.1% 和 0.01%。

**旁瓣（雷达水平面以下）：方向图因子用的是 |AF|，不是 |AF|²。**
- 原程序 `cal_Gthetaphi = G · |Eθ| · |Eφ|`，E 是阵因子 sin(Nu) / (N sin u)，即场强方向图。
- 数据中第一旁瓣峰值（偏离 0.667°）处 S R² / K = 0.2172 = |AF|，相当于 −6.6 dB；按功率方向图 |AF|² 应为 0.0472，即 −13.3 dB。
- 全部旁瓣节点的存储值与 |AF| 之比中位数为 1.000000。是否应改为 |AF|²，需作者确认原程序的意图。
